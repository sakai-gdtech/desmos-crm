Quero desenvolver um sistema completo de CRM SaaS multiempresa, pronto para ser utilizado por empresas reais.

O sistema deve ser moderno, escalável, seguro, intuitivo e visualmente profissional. Não quero apenas um CRUD de clientes. Quero uma plataforma que possa realmente ser utilizada diariamente por empresas para gerenciar leads, clientes, vendas, equipes comerciais, atividades, negociações, tarefas, relatórios e relacionamento com clientes.

O produto deve ser projetado desde o início como um SaaS multi-tenant.

# CONCEITO DO PRODUTO

Crie um CRM chamado provisoriamente de **Orbit CRM**.

O conceito principal do produto deve ser:

"Todo o relacionamento com o cliente em um único lugar."

Cada empresa terá seu próprio ambiente totalmente isolado.

Dentro de uma empresa existirão:

- usuários;
- equipes;
- vendedores;
- gestores;
- leads;
- clientes;
- empresas clientes;
- contatos;
- oportunidades;
- pipelines;
- etapas de vendas;
- atividades;
- tarefas;
- reuniões;
- notas;
- arquivos;
- propostas;
- produtos;
- histórico de interações;
- relatórios;
- automações;
- configurações.

A principal experiência do sistema deve girar em torno de uma **timeline de relacionamento**.

Ao abrir um lead, cliente ou empresa, o usuário deve conseguir visualizar rapidamente:

- quando o registro foi criado;
- quem criou;
- alterações realizadas;
- ligações;
- mensagens;
- emails;
- reuniões;
- tarefas;
- notas;
- oportunidades;
- propostas;
- mudanças de etapa;
- vendas fechadas;
- arquivos enviados;
- próximos compromissos.

O CRM precisa transmitir a sensação de que o usuário consegue entender toda a história daquele cliente em poucos segundos.

# MULTI-TENANCY

Este é um requisito crítico.

Cada empresa será um Tenant.

Estrutura conceitual:

Tenant
 ├── Users
 ├── Teams
 ├── Contacts
 ├── Companies
 ├── Leads
 ├── Pipelines
 ├── Deals
 ├── Activities
 ├── Tasks
 ├── Products
 ├── Proposals
 ├── Automations
 └── Settings

Nenhum usuário pode acessar dados de outro tenant.

Todas as entidades de negócio devem possuir tenantId quando necessário.

Nunca confiar em tenantId enviado diretamente pelo frontend sem validar a associação do usuário.

O backend deve identificar a empresa ativa através da sessão/contexto autenticado.

Um mesmo usuário poderá futuramente pertencer a mais de uma empresa.

Criar uma estrutura de membership:

User
Tenant
Membership

Membership deve possuir:

- id
- userId
- tenantId
- role
- status
- createdAt

Roles iniciais:

# OBJETIVO FINAL

O objetivo não é criar apenas um projeto bonito para portfolio.

O objetivo é desenvolver a base de um CRM SaaS que poderia realmente ser vendido e utilizado por pequenas e médias empresas.

O sistema deve conseguir atender, com customizações através de pipelines, campos personalizados, tags e automações, empresas de diferentes segmentos como:

agências;

software houses;

consultorias;

imobiliárias;

distribuidoras;

empresas B2B;

prestadores de serviço;

escritórios;

empresas comerciais.

Toda decisão de arquitetura deve considerar:

segurança;

isolamento de tenants;

manutenibilidade;

performance;

experiência do usuário;

crescimento futuro.

Não criar complexidade prematura.

Priorizar um excelente monólito modular antes de considerar microserviços.

Ao iniciar o projeto:

1. analise todos os requisitos;
2. proponha a arquitetura;
3. desenhe os principais fluxos;
4. modele o banco de dados;
5. defina módulos e responsabilidades;
6. apresente a estrutura de pastas;
7. apresente as principais entidades e relacionamentos;
8. defina estratégia multi-tenant;
9. defina autenticação e autorização;
10. crie um roadmap;
11. somente depois comece a implementação.

Não implemente centenas de arquivos de uma vez.

Desenvolva módulo por módulo, mantendo sempre o projeto executável e testável.
